# Interface localization

Open **Settings → Language** and choose **English** or **简体中文**. This browser preference applies immediately, survives reloads, and does not change the server's settings or other users' language. A saved choice wins over the browser language. Simplified Chinese browser preferences select `zh-Hans`; unsupported languages fall back to English.

## Coverage

Application-owned interface text uses the existing i18next + ICU pipeline throughout the current application:

| Entry / surface | Localized content |
| --- | --- |
| Shell and navigation | Desktop sidebar, mobile sheets, benchmark catalog, command palette, search labels, access-token and installation prompts |
| Overview | Fleet KPIs, energy / token cards, device summaries, health findings, recent activity, empty states |
| Settings / device dialogs | All settings, device kinds, roles, SSH and connection checks, optional services, validation and confirmations |
| Spark detail | GPU / CPU / RAM / storage / network / RoCE, chart tooltips, VRAM advice, LLM models and launchers, ComfyUI, Hermes and Tailscale |
| Token totals | Ranges, chart series and axes, summaries and insights, sortable tables, reset confirmations and export feedback |
| Fleet energy | Hourly / daily charts, costs, coverage and efficiency, monthly archive, node comparisons, insights and reset menus |
| Activity | Filters, counts, relative and absolute dates, clear confirmations, current events and recognized historical events |
| Showcase (embedded and standalone) | Controls, prompt-type labels and descriptions, terminal states, history, errors and share headings |
| Decode / Prefill / Quality | Standalone pages and dialogs, controls, progress, results, comparisons, history and share cards / text |
| Tool Eval | Setup, simple and advanced configuration, all 83 option labels / help and 15 groups mapped by stable IDs, presets, validation, progress, history and results / comparisons |
| Shared components | Clear / delete menus, alerts, restart, live terminals, chart descriptions, health and connectivity results |
| Server messages | Optional field-level descriptors for authored API errors, connection checks, job progress, health findings, activity and success notices |

Translated presentation preserves submitted option values, flag names, endpoint IDs, scenario contents and scoring. Locale-sensitive date formatters, chart/table labels, searches and memoized insights refresh when language changes. Open confirmation choices resolve their labels by stable ID. There is no separate Chinese documentation edition.

## Intentionally retained text

- Product, host, user, model and backend names; user-entered labels and external release notes / commit titles.
- Model output and reasoning, benchmark prompts and expected answers, scenario test content, raw process logs and commands.
- CLI flags, submitted enum values, protocol / API identifiers, paths, URLs, ports, environment variables and executable names.
- Standard units and technical abbreviations, including GPU, GB, kWh, tok/s, TTFT, MTU and RX/TX. Surrounding explanations are translated.
- CSV column identifiers remain stable for downstream readers; export controls and feedback are translated.
- Unknown external messages and unknown historical event types keep their original text. Unknown errors receive a translated explanation with the full original diagnostic detail.

Some source tables keep English baseline descriptors for compatibility while UI consumers project them through finite ID-based translation functions. These are translated when displayed. The AST audit lists each retained source string separately, including its reason and translating consumer, in [`scripts/i18n-retained-text.json`](../scripts/i18n-retained-text.json). There are no page-wide exemptions. CSS classes, ARIA enum values, URL builders and internal sentinels also have exact, documented exceptions.

## Server compatibility

The server returns original English fields and HTTP statuses. It adds optional `i18n` metadata indexed by field, for example:

```json
{"error":"Spark not found","i18n":{"error":{"key":"server.error.sparkNotFound"}}}
```

Each browser renders descriptors with its own preference. English uses the original field exactly. New browsers also recognize supported older messages and historical event types / structured data without rewriting stored records; unknown descriptors fall back to original fields. The JSON response middleware decorates only the top-level message object; power batch routes explicitly decorate their own rows. It never scans arbitrary benchmark results, logs, model text or command arguments. New persisted job / event snapshots omit derived descriptors, and API getters project them for presentation; existing files are not rewritten on read. A shared locale-neutral recognizer uses literal searches with a 4,096 UTF-16-code-unit budget and complete-message matching. Oversized text falls back to its full raw diagnostic without truncation.

## Contributing translations

English defaults live at each call site: `t("shell.nav.overview", "Overview")`. Chinese catalogs are in `src/locales/zh-Hans/`, split by product namespace. Use ICU placeholders such as `{name}` and `{count, plural, one {# item} other {# items}}`; do not use `{{name}}`.

Use `useTranslation()` in React components so they re-render after a language change. UI helpers can use the initialized i18next instance when called during render or an action. Include language in memo/cache dependencies when cached results contain translated text. Keep semantic state / IDs for later rendering instead of caching translated feedback strings. Pass numbers to ICU `count`; pass separately formatted numbers under other parameter names. Keep shared server-side protocol constants independent of the frontend i18n instance.

Catalogs load lazily. A failed load leaves the current language selected and can be retried from Settings. An older download cannot overwrite a newer language selection. Browser storage is optional; switching still works when storage is unavailable.

## Validation

```sh
npm run i18n:check -- --strict
npm run i18n:coverage
npm run test:i18n-coverage
npm run test:i18n-browser-config
npm run typecheck
npm run test:frontend
npm run test:server # Linux: collectors require native POSIX tools
npm run build
```

After building, `npm run test:i18n-browser` discovers installed Chromium / Chrome / Edge on Windows, macOS or Linux and launches a headless browser against a loopback-only fixture server. Set `I18N_BROWSER_BINARY` to explicitly select an executable; it is validated before the server starts. `I18N_BROWSER_OUT` selects an artifact directory (default `.omx/i18n-browser`, ignored by the shared `.gitignore`). Profiles use a unique OS temporary directory and only the owned profile is removed after the run. Linux root containers use `--no-sandbox`; non-root Linux runs keep the sandbox unless `I18N_BROWSER_NO_SANDBOX=1` is explicitly set. The suite uses random local ports, exercises all routes at desktop / phone sizes, switches through Settings, reloads to verify persistence, and tests delete / shutdown flows against synthetic data. Use a Node version supported by the lockfile's dependencies (for example Node 22.23.2); the fixture import requires TypeScript type stripping. It never contacts the deployed dashboard.

The key checker rejects missing translations, ICU parameter mismatches, orphan keys and dynamic translation calls. The separate AST checker examines visible JSX, display attributes, menu descriptors, feedback, error literals and returned labels. Exact exemptions need a rationale; duplicates and stale exemptions fail. Positive and negative fixtures test the checker itself. Neither checker alone proves whole-product coverage: inspect dynamic data and real browser output too.

Runtime tests exercise actual ICU catalogs, same-mount English → Chinese → English transitions, settings persistence / download races, chart and insight caches, presets and option projection invariance, legacy events, health data, error fallback and exact English compatibility. Browser acceptance covers each route on desktop and phone, dynamic menus and confirmations, refresh persistence, exposed keys and horizontal overflow. Use isolated test data for destructive flows. GPU/model execution is not implied by UI localization checks.
