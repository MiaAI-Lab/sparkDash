# Interface localization

Open **Settings → Language** and choose **English** or **简体中文**. This browser preference applies immediately, survives reloads, and does not change the server's settings or other users' language. A saved choice wins over the browser language. Simplified Chinese browser preferences select `zh-Hans`; unsupported languages fall back to English.

The initial Chinese coverage includes navigation and the command palette, Overview, Settings and device dialogs, Spark resource and service panels, decode/prefill/quality benchmark dialogs and share cards, and Activity labels and dates.

Coverage is partial. Token totals, Fleet energy, Showcase, Tool Eval and parts of the standalone benchmark screens still contain English. Raw backend errors, event messages and benchmark progress messages also retain their original wording. Product and model names, units and benchmark protocol identifiers stay unchanged. This change does not translate benchmark prompts or alter their scoring.

## Contributing translations

English defaults live at each call site: `t("shell.nav.overview", "Overview")`. Chinese catalogs are in `src/locales/zh-Hans/`, split by product namespace. Use ICU placeholders such as `{name}` and `{count, plural, one {# item} other {# items}}`; do not use `{{name}}`.

Use `useTranslation()` in React components so they re-render after a language change. UI helpers can use the initialized i18next instance when called during render or an action. Include language in memo/cache dependencies when cached results contain translated text. Keep shared server-side protocol constants independent of the frontend i18n instance.

Catalogs load lazily. A failed load leaves the current language selected and can be retried from Settings. An older download cannot overwrite a newer language selection. Browser storage is optional; switching still works when storage is unavailable.

## Validation

Run `npm run i18n:check -- --strict`, `npm run typecheck`, `npm run test:frontend`, and `npm run build`. The catalog checker checks translated keys and placeholders; it does **not** detect every remaining hard-coded string or prove whole-product translation coverage.

Tests cover persisted preference detection, switching both ways through Settings, settings API failure, failed catalog retry, a delayed catalog competing with a newer language choice, Activity formatter caches, and ICU formatting of shipped Chinese catalogs and double-quoted inline English defaults using the runtime plugin. Review desktop and mobile layouts and untranslated screens separately.
